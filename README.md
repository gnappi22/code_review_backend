# Code Review Backend Service

A FastAPI-based backend service that accepts code snippets and returns structured code reviews generated by OpenAI's GPT models. This service is designed to be integrated into GitHub PR workflows for automated code review assistance.

## Features

- **Code Snippet Submission**: Submit code snippets with language detection and line number information
- **AI-Powered Reviews**: Generate comprehensive code reviews using OpenAI's GPT-3.5-turbo model
- **Structured Responses**: Get reviews with summary, suggestions, and ratings
- **Persistent Storage**: SQLite database for storing snippets and reviews
- **RESTful API**: Clean, async-compatible endpoints
- **Docker Support**: Easy deployment with Docker and docker-compose

## API Endpoints

### POST /snippets
Submit a code snippet for review.

**Request Body:**
```json
{
  "language": "go",
  "code": "package main\nfunc main() { println(\"hello\") }",
  "lines": "56-57"
}
```

**Response:**
```json
{
  "id": 1,
  "language": "go",
  "code": "package main\nfunc main() { println(\"hello\") }",
  "lines": "56-57",
  "review": {
    "summary": "The code prints 'hello' but lacks error handling and clear structure.",
    "suggestions": [
      "Use `fmt.Println` instead of `println` for better formatting.",
      "Add comments describing the main function's purpose.",
      "Consider adding error handling for future extensibility."
    ],
    "rating": 7.0
  },
  "created_at": "2024-01-15T10:30:00Z"
}
```

### GET /snippets/{id}
Retrieve a specific snippet and its review by ID.

### GET /snippets
List all snippets with their reviews (supports pagination with `skip` and `limit` parameters).

### GET /
Health check endpoint.

## Quick Start

### Prerequisites

- Docker and Docker Compose
- OpenAI API key

### Environment Setup

1. Copy the environment example file:
```bash
cp env.example .env
```

2. Edit `.env` and add your OpenAI API key:
```
OPENAI_API_KEY=your_openai_api_key_here
DATABASE_URL=sqlite:///./data/code_review.db
```

### Running with Docker Compose

1. **Build and start the service:**
```bash
docker-compose up --build
```

2. **The service will be available at:**
- API: http://localhost:8000
- Interactive API docs: http://localhost:8000/docs
- Alternative API docs: http://localhost:8000/redoc

### Running Locally (Development)

1. **Install dependencies:**
```bash
pip install -r requirements.txt
```

2. **Set environment variables:**
```bash
export OPENAI_API_KEY=your_openai_api_key_here
export DATABASE_URL=sqlite:///./code_review.db
```

3. **Run the application:**
```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## Database Schema

The service uses SQLite with the following schema:

- **code_snippets** table:
  - `id`: Primary key
  - `language`: Programming language
  - `code`: Code snippet content
  - `lines`: Line number range (optional)
  - `created_at`: Timestamp
  - `review_summary`: AI-generated review summary
  - `review_suggestions`: JSON array of suggestions
  - `review_rating`: Numerical rating (1-10)

## Configuration

### Environment Variables

- `OPENAI_API_KEY`: Your OpenAI API key (required)
- `DATABASE_URL`: Database connection string (default: SQLite)

### OpenAI Model Configuration

The service uses GPT-3.5-turbo by default. You can modify the model in `app/llm_service.py`:

```python
response = self.client.chat.completions.create(
    model="gpt-3.5-turbo",  # Change this to gpt-4 or other models
    # ... other parameters
)
```

## Development Notes

### Technology Choices

- **FastAPI**: Chosen for its excellent async support, automatic API documentation, and type safety
- **SQLAlchemy**: Provides robust ORM with good async support and database abstraction
- **SQLite**: Simple, file-based database perfect for development and small deployments
- **OpenAI GPT-3.5-turbo**: Cost-effective model with good code review capabilities

### Error Handling

The service includes comprehensive error handling for:
- Invalid API keys
- Network connectivity issues
- Malformed requests
- Database errors
- LLM API failures

### Security Considerations

- API key validation
- Input sanitization
- SQL injection prevention (via SQLAlchemy ORM)
- Rate limiting (can be added via middleware)

## Troubleshooting

### Common Issues

1. **OpenAI API Key Error**: Ensure your API key is valid and has sufficient credits
2. **Database Connection Issues**: Check that the data directory is writable
3. **Port Conflicts**: Change the port in docker-compose.yml if 8000 is occupied
